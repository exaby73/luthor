A validator with no `.required()` accepts `null`. Inside a schema, it also accepts a missing field. This is the opposite of Zod, where every schema is required until you call `.optional()`, and it is deliberate.

## The design choice

Dart's null safety is explicit: a `String?` says in the type that the value may be absent, and a `String` says it may not. Luthor follows the same rule. The validator describes the shape of a value when it is present. Whether it has to be present is a separate decision, so it is a separate modifier.

The generator depends on this. It maps a Dart type to a validator and then adds `.required()` when the parameter is non-nullable and has no `@Default`. A `String? nickname` becomes `l.string()`, a `String name` becomes `l.string().required()`. The schema and the type agree without any extra annotation.

## What optional means

For a single value, every type and modifier validation accepts `null`. A [custom validator](/concepts/custom-validators) is the exception: it receives `null` and decides for itself.

<Verdict
  title="l.string().email().validateValue(input)"
  cases={[
    { input: 'null', pass: true },
    { input: "'dev@example.com'", pass: true },
    { input: "'bad'", pass: false, message: 'value must be a valid email address' },
  ]}
/>

For a schema field, a missing key skips every validation on that field, including custom validators. A schema custom validator on an optional field never runs for input that leaves the field out. A key that is present with a `null` value is validated like a single value. If a check only makes sense when the field exists, make the field required, or attach the check to a field that is always present.

```dart
final schema = l.schema({
  'email': l.string().email().required(),
  'nickname': l.string().min(2),
});

schema.validateSchema({'email': 'dev@example.com'}).isValid;                  // true
schema.validateSchema({'email': 'dev@example.com', 'nickname': null}).isValid; // true
schema.validateSchema({'email': 'dev@example.com', 'nickname': 'x'}).isValid;  // false
```

## What required means

`.required()` adds one validation: the value is not `null`. A missing schema field counts as `null`. It says nothing about emptiness. An empty string or an empty list passes `.required()`. Use `.min(1)` on a string, or a custom validator on a list, when you need content.

<Verdict
  title="l.string().required().validateValue(input)"
  cases={[
    { input: "''", pass: true },
    { input: 'null', pass: false, message: 'value is required' },
  ]}
/>

Required in Luthor is unrelated to Dart's `required` keyword. The keyword decides whether a caller has to pass an argument. The modifier decides whether `null` is a valid value. The generator reads nullability, not the keyword: `required String? note` produces an optional validator.

## Where `.required()` goes in a chain

Put `.required()` last. Type-specific modifiers such as `.email()` and `.min()` belong before it, so the type and its modifiers read as one unit and the chain type-checks.
