---
title: Schema keys and error keys
description: The two generated records that replace string literals when you read input maps and error maps.
---

For a model `User`, the generator emits two records: `UserSchemaKeys` and `UserErrorKeys`. Both have one field per constructor parameter, named after the Dart parameter. They differ in what the field holds. The examples use the `User` and `Address` models from [What gets generated](/generator/output).

## Schema keys

Each field of `UserSchemaKeys` holds the key of that field in the input map. That is the parameter name, or the `@JsonKey(name:)` value when there is one. The generated schema is written with these keys, and you can use them to read the raw map without repeating the string.

```dart
const UserSchemaKeys = (
  name: "name",
  email: "email_address", // from @JsonKey(name: 'email_address')
  age: "age",
  address: "address",
);

final raw = json[UserSchemaKeys.email];
```

## Error keys

Each field of `UserErrorKeys` holds the error path of that field, the string you would pass to `getError`. A field whose type is another model becomes a nested record whose paths carry the prefix, so the record mirrors the error map.

```dart
const UserErrorKeys = (
  name: "name",
  email: "email_address",
  age: "age",
  address: (
    street: "address.street",
    city: "address.city",
    postcode: "address.postcode",
  ),
);
```

Use them with `getError`:

```dart
switch ($UserValidate(json)) {
  case SchemaValidationSuccess(data: final user):
    save(user);
  case SchemaValidationError():
    final emailError = result.getError(UserErrorKeys.email);
    final postcodeError = result.getError(UserErrorKeys.address.postcode);
}
```

Rename `postcode` in `Address` and `UserErrorKeys.address.postcode` stops compiling, which is the point. A string literal would have kept compiling and started returning `null`.

## Self-referential models

When a model refers to itself, the nested record would be infinite. The generator stops at the first repeat and emits the path as a plain string for that field. For `Comment` with `Comment? parent`, `CommentErrorKeys.parent` is the string `"parent"`, and deeper paths are written by hand.

## Where the keys are used

`UserSchemaKeys` appears in `$UserSchema`. `UserErrorKeys` is for your code. Neither record has a type name; both are anonymous Dart records, so pass them to functions as `({String name, String email, ...})` or let inference carry them.
