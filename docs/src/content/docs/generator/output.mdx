---
title: What gets generated
description: The five items luthor_generator writes for every @luthor model, with the generated code for one model.
---

For each class annotated with `@luthor`, the generator writes five items into the `part` file: a generated schema, a validate function, a `validateSelf` extension, schema keys, and error keys. This page shows all five for one model. The pages that follow use the same `User` and `Address`.

## The models

```dart title="lib/user.dart"
import 'package:freezed_annotation/freezed_annotation.dart';
import 'package:luthor/luthor.dart';

part 'user.freezed.dart';
part 'user.g.dart';

@luthor
@freezed
abstract class User with _$User {
  const factory User({
    @HasMin(2) required String name,
    @IsEmail() @JsonKey(name: 'email_address') required String email,
    @HasMin(18) int? age,
    required Address address,
  }) = _User;

  factory User.fromJson(Map<String, dynamic> json) => _$UserFromJson(json);
}

@luthor
@freezed
abstract class Address with _$Address {
  const factory Address({
    required String street,
    required String city,
    @MatchRegex(r'^\d{5}$') required String postcode,
  }) = _Address;

  factory Address.fromJson(Map<String, dynamic> json) => _$AddressFromJson(json);
}
```

## Generated schema

`$UserSchema` is a top-level `Validator`. Each field's validator is derived from the parameter type and its annotations. [Supported field types](/generator/types) lists the mapping. The schema is named after the model with `withName`.

```dart title="lib/user.g.dart"
Validator $UserSchema = l.withName('User').schema({
  UserSchemaKeys.name: l.string().min(2).required(),
  UserSchemaKeys.email: l.string().email().required(),
  UserSchemaKeys.age: l.int().min(18),
  UserSchemaKeys.address: $AddressSchema.required(),
});

Validator $AddressSchema = l.withName('Address').schema({
  AddressSchemaKeys.street: l.string().required(),
  AddressSchemaKeys.city: l.string().required(),
  AddressSchemaKeys.postcode: l.string().regex("^\\d{5}\$").required(),
});
```

String literals in generated code are double-quoted and escaped, so `r'^\d{5}$'` appears as `"^\\d{5}\$"`.

## Validate function

`$UserValidate` runs `validateSchema` with the model's `fromJson`, so success carries a `User`.

```dart title="lib/user.g.dart"
SchemaValidationResult<User> $UserValidate(Map<String, dynamic> json) =>
    $UserSchema.validateSchema(json, fromJson: User.fromJson);
```

For a `dart_mappable` model the function uses `UserMapper.fromMap` instead.

## `validateSelf` extension

The extension serialises an instance with `toJson()` and validates the result, which is how you check a model you built in code rather than parsed from input.

```dart title="lib/user.g.dart"
extension UserValidationExtension on User {
  SchemaValidationResult<User> validateSelf() => $UserValidate(toJson());
}
```

`toJson()` has to produce nested maps for nested models. `json_serializable` leaves nested objects as instances unless `explicit_to_json` is on, and the nested schema then reports `value must be a map`. Turn it on in `build.yaml`:

```yaml title="build.yaml"
targets:
  $default:
    builders:
      json_serializable:
        options:
          explicit_to_json: true
```

`dart_mappable` models use `toMap()`, which already nests.

## Schema keys

`UserSchemaKeys` is a record. Each field is named after the Dart parameter and holds the key as it appears in the input map, which is the `@JsonKey` name when there is one. The generated schema uses these keys, and you can use them when you read the raw map.

```dart title="lib/user.g.dart"
const UserSchemaKeys = (
  name: "name",
  email: "email_address",
  age: "age",
  address: "address",
);
```

## Error keys

`UserErrorKeys` has the same fields, but each holds an error path for `getError`. A field whose type is another model becomes a nested record whose paths are prefixed.

```dart title="lib/user.g.dart"
const UserErrorKeys = (
  name: "name",
  email: "email_address",
  age: "age",
  address: (
    street: "address.street",
    city: "address.city",
    postcode: "address.postcode",
  ),
);
```

```dart
result.getError(UserErrorKeys.address.postcode); // postcode must match regex
```

[Schema keys and error keys](/generator/keys) goes into both records.

## Auto-generated schemas

When a field's type is a class that has no `@luthor` annotation but has a `fromJson` factory or `@MappableClass` and a constructor with named parameters, the generator emits the same five items for that class too, after the annotated model's. These are auto-generated schemas. When two annotated models in one library refer to the same un-annotated class, each emits a copy, which does not compile. Annotate the shared class with `@luthor` instead.
