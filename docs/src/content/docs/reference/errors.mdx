---
title: 'Error messages'
description: Every default message, how the field name is filled in, and the shapes an error map can take.
---

Each validation has one default message. A field name replaces `value` when the validator is a schema field or was named with `withName`. `message` and `messageFn` override the default per call. [Message functions](/concepts/messages) covers the overrides.

## Default messages

| Validation | Default message |
|---|---|
| `l.string()` | `value must be a string` |
| `l.int()` | `value must be an integer` |
| `l.double()` | `value must be a double` |
| `l.number()` | `value must be a number` |
| `l.boolean()` | `value must be a bool` |
| `l.list()` | `value must be a list`, or `value must be a list or does not match the validations` with element validators |
| `l.map()` | `value must be a Map` |
| `l.schema()` on a non-map | `value must be a map` |
| `l.file()` | `value must be a file` |
| `l.nullValue()` | `value must be null` |
| `.required()` | `value is required` |
| `.custom()` | `value does not pass custom validation` |
| `.customWithSchema()` | `value does not pass schema custom validation` |
| `.min(n)` on a string | `value must be at least n characters long` (`1 character long` for 1) |
| `.max(n)` on a string | `value must not be more than n characters long` |
| `.length(n)` | `value must be exactly n characters long` |
| `.contains(s)` | `value does not contain "s"` |
| `.startsWith(s)` | `value does not start with "s"` |
| `.endsWith(s)` | `value does not end with "s"` |
| `.regex(p)` | `value must match regex` |
| `.email()` | `value must be a valid email address` |
| `.uri()` | `value must be a valid uri`, plus `. Allowed scheme is x` or `. Allowed schemes are x, y` |
| `.url()` | `value must be a valid URL`, plus the same scheme suffix |
| `.ip()` | `value must be a valid IP address`, `IPv4 address`, or `IPv6 address` |
| `.uuid()` | `value must be a valid uuid` |
| `.cuid()` | `value must be a valid cuid` |
| `.cuid2()` | `value must be a valid cuid2` |
| `.dateTime()` | `value must be a valid date` |
| `.emoji()` | `value must be a valid emoji` |
| `.min(n)` on a number | `value must be greater than or equal to n` |
| `.max(n)` on a number | `value must be less than or equal to n` |

## Messages accumulate

Validations do not short-circuit. Every validation on the chain runs and every failure adds a message, so `l.int().min(5).validateValue('x')` reports both `value must be an integer` and `value must be greater than or equal to 5`.

## Error map shapes

Single-value validation returns a `List<String>`. Schema validation returns a map keyed by field name whose values take one of these shapes:

| Field validator | Value in the error map |
|---|---|
| A chain such as `l.string().email()` | `List<String>` of messages |
| A nested `l.schema()` | A nested error map with the same rules |
| `l.map()` with key or value validators | `{'keys': {key: [...]}, 'values': {key: [...]}}` |
| `l.list()` | `List<String>` with one message for the whole list |

Fields that passed do not appear. `getError('a.b')` walks nested maps by error path and returns the first message in the list it reaches. When `validateValue` is used on a map validator, the `keys` and `values` structure is flattened to `key: message` strings.
