---
title: 'forwardRef()'
description: Refer to a validator that is defined later, or to the schema being defined.
---

`forwardRef()` wraps a function that returns a validator. Luthor calls the function at validation time, so the validator it returns can be one that is still being defined when the schema literal is built. [Schemas](/concepts/schemas) has the explanation; this page lists the facts.

## Signature

```dart wrap
ValidatorReference forwardRef(Validator Function() resolver)
```

`ValidatorReference` is the interface shared by `Validator` and forward references. It has one method, `resolve()`, which returns the `Validator`. Every place that takes a validator inside a schema, a list, or a map is typed as `ValidatorReference`, so a forward reference fits wherever a validator does.

## Parameters

| Parameter | Type | Meaning |
|---|---|---|
| `resolver` | `Validator Function()` | Called each time the reference is resolved. Return the validator to use, with any modifiers such as `.required()` applied inside the function. |

## Example

```dart
late final Validator node;
node = l.schema({
  'value': l.string().required(),
  'children': l.list(validators: [forwardRef(() => node.required())]),
});
```

Two schemas that refer to each other follow the same pattern: declare both as `late final` and wrap each reference to the other.

## Code generation

The generator wraps a field in `forwardRef()` when the field's type is the model's own class, directly or as a `List` element or `Map` value. For a reference from one model to a different model that refers back, annotate the parameter with `@luthorForwardRef`.

```dart wrap
List<Comment>? replies,        // forwardRef(() => $CommentSchema.required()) inside l.list()
@luthorForwardRef User? user,  // forwardRef(() => $UserSchema)
```
