Luthor never throws for invalid input. Each validation call returns a sealed result with a success case and an error case. This page describes both results and the error map that schema validation produces. [The reference](/reference/results) lists the members.

## Single-value validation

`validateValue` returns `SingleValidationResult<T>`, where `T` is the type of the value you passed in.

```dart
final result = l.string().min(8).contains('@').validateValue('ab');

switch (result) {
  case SingleValidationSuccess(data: final value):
    // value is 'ab'
  case SingleValidationError(data: final value, errors: final errors):
    // errors is a List<String>:
    // [value must be at least 8 characters long, value does not contain "@"]
}
```

`isValid` is available on both cases for the times you only need a boolean. `data` is the input, unchanged, on both cases.

## Schema validation

`validateSchema` returns `SchemaValidationResult<T>`. Without `fromJson`, `T` is the input map type and `data` is the input. With `fromJson`, `T` is your model, `data` is the converted model on success, and `data` is `null` on failure because conversion did not run.

```dart
final result = userSchema.validateSchema<User>(json, fromJson: User.fromJson);

switch (result) {
  case SchemaValidationSuccess(data: final user):
    // user is a User
  case SchemaValidationError(errors: final errors):
    // errors is a Map<String, dynamic>
}
```

## The error map

A schema error holds an error map keyed by field name. A field whose validator is a plain chain maps to a `List<String>` of messages. A field whose validator is a nested schema maps to a nested error map. Fields that passed are absent.

```dart
final user = l.schema({
  'email': l.string().email().required(),
  'age': l.int().min(18),
  'profile': l.schema({
    'displayName': l.string().min(2).required(),
  }).required(),
});

user.validateSchema({
  'email': 'bad',
  'age': 12,
  'profile': {'displayName': 'x'},
});
```

The error map for that input:

```dart
{
  'email': ['email must be a valid email address'],
  'age': ['age must be greater than or equal to 18'],
  'profile': {
    'displayName': ['displayName must be at least 2 characters long'],
  },
}
```

A map field validated with `keyValidator` or `valueValidator` nests its messages under `keys` and `values`, so a map that happens to contain a key named `keys` cannot collide with them. [`l.map()`](/reference/types/map) shows the shape.

## Error paths and `getError`

`SchemaValidationError.getError` takes an error path, a dot-separated chain of field names, and returns the first message at that path, or `null` when the field passed.

```dart
if (result case SchemaValidationError()) {
  result.getError('email');               // email must be a valid email address
  result.getError('profile.displayName'); // displayName must be at least 2 characters long
  result.getError('profile');             // null: profile holds a nested map, not messages
}
```

`getError` throws a `StateError` if the path points at a nested map rather than a list of messages, as in the last line's sibling case where `profile` itself failed with nested errors. Ask for the leaf field.

With the generator, the `ErrorKeys` record holds every error path of a model as a typed constant, so `result.getError(UserErrorKeys.profile.displayName)` replaces the string. [Schema keys and error keys](/generator/keys) covers it.

## Printing a result

Both result types override `toString`, which is what the examples on this site print:

```txt
SingleValidationSuccess(data: dev@example.com)
SingleValidationError(data: bad, errors: [value must be a valid email address])
SchemaValidationError(data: {email: bad}, errors: {email: [email must be a valid email address]})
```
