The generator needs two things from a class: a constructor with named parameters, and a way to convert a map to an instance. `freezed` supplies both, but it is not required. This page shows the three other setups with the same `User` model, and the generated code for each.

## What the generator needs

- The class is annotated with `@luthor`.
- A constructor with named parameters. The schema follows the constructor the serializer uses: the one named in `@JsonSerializable(constructor:)`, the `@MappableConstructor`, the unnamed constructor, or else the first public constructor with parameters.
- Either a `fromJson` factory, generative constructor or static method, or the `@MappableClass` annotation from `dart_mappable`.
- For `validateSelf`, a `toJson()` method or `dart_mappable`'s `toMap()`. Without one, the extension is not generated.

No `build.yaml` is needed. The builder applies `source_gen`'s combining builder, so a `.g.dart` is produced even without `json_serializable`.

```dart title="lib/user.dart"
import 'package:json_annotation/json_annotation.dart';
import 'package:luthor/luthor.dart';

part 'user.g.dart';

@luthor
@JsonSerializable(fieldRename: FieldRename.snake)
class User {
  const User({required this.fullName, required this.email, this.age});

  factory User.fromJson(Map<String, dynamic> json) => _$UserFromJson(json);

  @HasMin(2)
  final String fullName;
  @IsEmail()
  final String email;
  @HasMin(18)
  final int? age;

  Map<String, dynamic> toJson() => _$UserToJson(this);
}
```

```sh
dart pub add luthor
dart pub add dev:build_runner dev:luthor_generator
```

```dart title="lib/user.dart"
import 'package:luthor/luthor.dart';

part 'user.g.dart';

@luthor
class User {
  const User({
    @HasMin(2) required this.name,
    @IsEmail() required this.email,
    @HasMin(18) this.age,
  });

  factory User.fromJson(Map<String, dynamic> json) => User(
    name: json['name'] as String,
    email: json['email'] as String,
    age: json['age'] as int?,
  );

  final String name;
  final String email;
  final int? age;

  Map<String, dynamic> toJson() => {'name': name, 'email': email, 'age': age};
}
```

A hand-written `fromJson` has to read only the keys of its constructor parameters, because the schema strips every other key before `fromJson` runs.

## What the serializer tells the generator

The generator reads the serializer's annotations so the schema matches what `fromJson` will do:

| Annotation | Effect on the schema |
|---|---|
| `@JsonKey(name:)`, `@JsonSerializable(fieldRename:)` on the class or the `freezed` factory | The key |
| `@MappableField(key:)`, `@MappableClass(caseStyle:)` | The key |
| `@JsonKey(defaultValue:)`, a constructor default, `@Default` | The field is optional |
| `@JsonKey(includeFromJson: false)` | The field is left out |
| `@JsonKey(fromJson:)`, a `JsonConverter` on the field, class or `@JsonSerializable(converters:)` | The field is `l.any()` |
| `@JsonKey(readValue:)` | The field is an optional `l.any()` and the schema gets `.passthrough()` |
| `@JsonSerializable(createToJson: false)`, `@Freezed(toJson: false)` | No `validateSelf` |
| Public settable fields on a `@JsonSerializable` class that are not constructor parameters | Schema fields, required unless nullable or defaulted |

Global options in another builder's `build.yaml`, such as `json_serializable`'s `field_rename`, are not read. Put them on the class.

## Classes you do not annotate

A field whose type is a class without `@luthor` still gets a schema, as long as that class meets the requirements above. The generator emits a private `_$ClassSchema` for it in the library that uses it, without public keys or a validate function. Annotate the class with `@luthor` when you want those.
