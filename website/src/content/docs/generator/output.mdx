For each class annotated with `@luthor`, the generator writes five items into the `part` file: a generated schema, a validate function, a `validateSelf` extension, schema keys, and error keys. This page shows all five for one model. The generated code is copied from a real `build_runner` run on the model below. The pages that follow use the same `User` and `Address`.

## The models

```dart title="lib/user.dart"
import 'package:freezed_annotation/freezed_annotation.dart';
import 'package:luthor/luthor.dart';

part 'user.freezed.dart';
part 'user.g.dart';

enum Role { admin, member }

@luthor
@freezed
abstract class User with _$User {
  const factory User({
    @HasMin(2) required String name,
    @IsEmail() @JsonKey(name: 'email_address') required String email,
    @HasMin(18) int? age,
    @Default(Role.member) Role role,
    required Address address,
  }) = _User;

  factory User.fromJson(Map<String, dynamic> json) => _$UserFromJson(json);
}

@luthor
@freezed
abstract class Address with _$Address {
  const factory Address({
    required String street,
    required String city,
    @MatchRegex(r'^\d{5}$') required String postcode,
  }) = _Address;

  factory Address.fromJson(Map<String, dynamic> json) => _$AddressFromJson(json);
}
```

## Generated schema

`$UserSchema` is a `final SchemaValidator`. Each field's validator is derived from the parameter type and its annotations; [Supported field types](/generator/types) lists the mapping. The enum becomes `l.oneOf()` of its names, the default makes `role` optional, and the nested model is referenced through `forwardRef()`. The schema is named after the model with `withName`.

`$UserValidate` accepts any input and runs `validateSchema` with the model's `fromJson`, so success carries a `User`.

## `validateSelf` extension

The extension serialises an instance with `toJson()`, converts any nested objects left as instances, and validates the result. It is how you check a model you built in code rather than parsed from input. It is generated only for models with a `toJson()` or a `dart_mappable` `toMap()`.

<Generated file="user.g.dart" from="extension UserValidationExtension" to="}" title="lib/user.g.dart" />

```dart
final user = User(
  name: 'A',
  email: 'ada',
  address: const Address(street: 's', city: 'c', postcode: '12345'),
);
print(user.validateSelf());
```

## Schema keys

`UserSchemaKeys` is a record. Each field is named after the Dart parameter and holds the key as it appears in the input map, which is the `@JsonKey` name when there is one. The generated schema uses these keys.

<Generated file="user.g.dart" from="const UserSchemaKeys" to=");" title="lib/user.g.dart" />

## Error keys

`UserErrorKeys` has the same fields, but each holds an error path for `getError`. A field whose type is another model becomes a nested record whose paths carry the prefix, with `$key` for the field's own path.

<Generated file="user.g.dart" from="const UserErrorKeys" to=");" title="lib/user.g.dart" />

```dart
print(result.getError(UserErrorKeys.email));
print(result.getError(UserErrorKeys.address.postcode));
print(result.getError(UserErrorKeys.address.$key));
print(UserSchemaKeys.email);
print(UserErrorKeys.address.$key);
```

## Unknown keys

A generated schema strips keys it does not declare before `fromJson` runs, like every 1.0 schema, so input with extra keys validates and the extras never reach the serializer:

<Output id="gen.user.unknown" title="$UserValidate({..., 'nickname': 'A', 'address': {..., 'country': 'FR'}}).isValid" />

Every key the serializer reads has to be a schema field, and the generator makes it one: for a `@JsonSerializable` class, public settable fields that are not constructor parameters are schema fields too. When the serializer may read keys the generator cannot name, the schema gets `.passthrough()` instead: a field with `@JsonKey(readValue:)`, a private field with `@JsonKey(includeFromJson: true)`, or a `@MappableClass(hook:)`.

## Auto-generated schemas

When a field's type is a class without `@luthor` that has a `fromJson` or `@MappableClass` and a constructor with named parameters, the generator emits a private schema for it, `_$ClassSchema`, once per library. It gets no public keys, validate function or extension. Annotate the class with `@luthor` to get the public API.

## Which constructor

The schema follows the constructor the serializer uses: the one named in `@JsonSerializable(constructor:)`, the `@MappableConstructor`, the unnamed constructor, or else the first public constructor with parameters.
