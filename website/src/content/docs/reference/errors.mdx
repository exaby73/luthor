## Field names

The name in a message is decided by where the validator runs:

| Where | Field name |
|---|---|
| Validated directly, no `withName` | `value` |
| Validated directly, after `.withName('x')` | `x` |
| A schema field | the field key, so `email is required` |
| An element of a list field | the list's field name, so `tags must be a string` at path `tags.1` |
| A value of a map field | the map's field name |
| A key of a map field | `key`, unless the key validator has a `withName` |
| A nested schema that is not a map | the nested field's key, so `profile must be a map` |
| Validated directly and not a map | `value must be a map`, or the schema's `withName` |

Messages do not include the path. Read `issue.errorPath` or the key of the error map for that.

## Messages for list and map input

Each failing element of a list reports at its index, and a map reports values at their key and keys as `invalidKey` issues at the map's path:

```dart
l.list(l.string().required()).validate(['a', 1, null]).errors;
// {1: [value must be a string], 2: [value is required]}

l.map(keyValidator: l.string().email().required(), valueValidator: l.int().required())
    .validate({'not-an-email': 'x'})
    .errors;
// {: [value has an invalid key "not-an-email"], not-an-email: [value must be an integer]}
```

[Errors and error paths](/concepts/errors) describes the error map in full.
