Returns a copy of the schema that fails when the input has a key the schema does not declare. Each unknown key produces one `unrecognizedKey` issue at that key's path, with `params['key']`. It is the same as [`.unknownKeys(.strict)`](/reference/schema/unknown-keys). Only `SchemaValidator` has this method.

## Signature

```dart wrap
SchemaValidator<O> strict({String? message, MessageBuilder? messageBuilder})
```

## Parameters

| Parameter | Type | Meaning |
|---|---|---|
| `message` | `String?` | Replaces the default error message. |
| `messageBuilder` | `MessageBuilder?` | Builds the message from the issue. `message` wins when both are given. See [Message builders](/concepts/messages). |

## Issue

Code `unrecognizedKey`. Default message: `role is not an allowed key`, where `role` is the unknown key.

## Code generation

The generator emits `.strict()` for a model annotated `@Luthor(unknownKeys: .strict)`. Under the `unknown_keys: strict` builder option, it also emits it for every model without its own `unknownKeys`, except a model whose serializer reads keys the generator cannot name, which gets `.passthrough()`. See [Unknown keys](/generator/output#unknown-keys).
