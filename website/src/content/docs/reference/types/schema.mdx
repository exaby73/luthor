Passes when the value is a map and every declared field passes its validator. A missing field is skipped unless its validator is required. Unknown keys are stripped from the output by default; [`.passthrough()`](/reference/schema/passthrough) keeps them and [`.strict()`](/reference/schema/strict) rejects them. The output is a new `Map<String, Object?>` with the validated value of each present field. Validate with `validate`, or with `validateSchema` to convert the output with `fromJson`. [Schemas](/concepts/schemas) explains nesting, reuse and forward references.

## Signature

```dart wrap
SchemaValidator<Map<String, Object?>?> schema(Map<String, ValidatorReference<Object?>> fields, {String? message, MessageBuilder? messageBuilder})

ValidationResult<T> validateSchema<T>(Object? input, {required FromJson<T> fromJson})
```

## Parameters

| Parameter | Type | Meaning |
|---|---|---|
| `fields` | `Map<String, ValidatorReference<Object?>>` | Field name to validator. Values may be validators, nested schemas, or forward references. |
| `message` | `String?` | Replaces the default error message. |
| `messageBuilder` | `MessageBuilder?` | Builds the message from the issue. `message` wins when both are given. See [Message builders](/concepts/messages). |

## Issue

Code `invalidType`. Default message: `value must be a map` when the value is not a map; `message` and `messageBuilder` apply to that case only. Field failures carry their own code at the field's path and use the field key as the field name. A `fromJson` that throws produces `value could not be converted` with code `fromJsonFailed`, and `null` input to `validateSchema` produces a `required` issue.

## Code generation

Every `@luthor` model produces `final SchemaValidator $ModelSchema`, and a field whose type is another model refers to that model's schema through `forwardRef()`. [What gets generated](/generator/output) shows the whole output.
